# iDryerMod

[English version](README.md)

Прошивка двухкатушечной сушилки филамента на ESP32-WROOM-32D.
Главная идея: **держать пластик сухим** — пресет не просто поддерживает
температуру заданное время, а сушит катушку, пока она реально не высохнет,
затем переходит на температуру хранения и автоматически досушивает при
возвращении влаги (открыли крышку, положили новую катушку).

Текущая версия прошивки: **0.2.1**

## Основные возможности

- **Пресеты «до сухости»** — каждый пресет задаёт минимальное время активной
  сушки, потолок безопасности, температуру хранения и порог сухости. Сушка
  идёт, пока катушка не перестанет отдавать влагу, затем камера переходит в
  малопотребляющую фазу Hold и следит за повторным увлажнением.
- **Оценка сухости по воздуху камеры** — при закрытой заслонке рост
  абсолютной влажности (AH) — это влага, отданная пластиком. Наклон,
  посчитанный методом наименьших квадратов по закрытому окну измерения
  (г/м³ в час), и есть сигнал сухости; весовые датчики для него не нужны.
- **Каскад температуры** — PID температуры воздуха выдаёт *уставку
  нагревателя (NTC)*, ограниченную `[цель воздуха .. лимит нагревателя −
  5 °C]`; внутренний термостат (гистерезис ±1 °C) коммутирует мосфет
  полностью вкл/выкл. Нагреватель никогда не греется сильнее, чем нужно
  камере.
- **Импульсная вентиляция** — цикл `Sealed → Purge → Settle`: заслонка
  закрыта, пока влага накапливается (и измеряется); короткая продувка
  обновляет воздух, когда AH выросла на ≥ 0,5 г/м³ от базы окна или дошла до
  защитного потолка насыщения. Вентилятор работает на тихом циркуляционном
  режиме при закрытой заслонке и на бусте только во время продувок.
- **Безопасность прежде всего** — interlock вентилятора на уровне
  актуаторов гарантирует обдув при любом включённом нагреве
  (`нагрев ⇒ вентилятор ≥ минимума`, применяется в порядке «сначала
  вентилятор»), поверх ворот лимита NTC и аппаратного термопредохранителя.
- **Два HX711** — телеметрия веса по каждой катушке с калибровкой
  tare/scale и таблицей термокомпенсации дрейфа на 16 диапазонов по 5 °C.
- **Веб-панель и REST API** по Wi-Fi с mDNS (`dryer.local`), историей
  телеметрии в LittleFS, опциональной HTTP Basic аутентификацией.
- **OTA-обновления по Wi-Fi** — и ArduinoOTA, и веб-эндпоинт; USB-кабель
  нужен только для первой прошивки.
- **Локальный интерфейс** — SH1106 OLED + меню на энкодере.
- **19 нативных юнит-тестов** логики управления, запускаются на хосте.

## Железо

| Функция | GPIO | Примечания |
|---|---:|---|
| I²C SDA / SCL | 21 / 22 | AHT30 + дисплей, 400 кГц |
| Энкодер A / B / кнопка | 32 / 33 / 25 | |
| Мосфет нагревателя | 26 | PTC 24 В через логический N-MOSFET |
| Мосфет вентиляторов | 27 | два вентилятора 24 В параллельно, PWM 20 кГц |
| Сервопривод заслонки | 14 | питание от отдельного источника 5–6 В |
| NTC (паз нагревателя) | 34 | ADC1, делитель 10 кОм / B=3950 |
| HX711 №1 DOUT/SCK | 16 / 17 | |
| HX711 №2 DOUT/SCK | 18 / 19 | |

Датчики: AHT30 (T/RH воздуха камеры), NTC в пазу PTC (температура
нагревателя), 2 × HX711 с 4-проводными тензодатчиками. Термопредохранитель
на 120 °C, включённый последовательно с нагревателем, остаётся независимым
аппаратным уровнем защиты, который ПО не заменяет.

Расчёты силовой части, математика делителя NTC и рекомендации по монтажу —
в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Архитектура управления

```
цель воздуха ──► [PID воздуха] ──► уставка нагревателя (NTC) ──► [термостат ±1°C] ──► мосфет вкл/выкл
                      ▲                  ограничена [цель .. лимит−5°C]
                      │
                 AHT30, T воздуха

цель AH ──► [PurgeScheduler]  Sealed ──► Purge ──► Settle ──► Sealed ...
                │                 ▲         │
                │                 │         └─ продувка: заслонка открыта, вентилятор буст
                │                 └─ триггер: рост AH ≥ 0.5 г/м³ или насыщение
                │
          [AhSlopeEstimator]  наклон AH за закрытое окно
                │
          сухость: наклон < порога 2 окна подряд
```

- **Политика вентилятора**: циркуляционный режим при закрытой заслонке
  (обдув нагревателя + перемешивание), буст во время продувки/перемешивания;
  всегда не ниже настроенного минимума при включённом нагреве. Вентилятор не
  гоняется на максимум просто потому что может.
- **Фаза Hold**: после сушки камера держит температуру хранения пресета и
  продолжает измерения. Если влага вернулась (`drynessChecks` сброшен),
  автомат сам возвращается в Drying со свежим бюджетом времени.
- **Ручной режим** остаётся простым обратным отсчётом; **непрерывный
  режим** держит условия до команды остановки.

Пороги сухости (0,3 г/м³/ч) и тайминги окон — **эмпирические первые
прикидки**; они выведены в телеметрию (`dryness.*` в `/api/state`) и должны
быть откалиброваны по логам на реальных катушках.

## Сборка и прошивка

```powershell
# полная сборка
pio run -e esp32dev

# прошивка по USB (первый раз)
pio run -e esp32dev -t upload
pio run -e esp32dev -t uploadfs        # ресурсы веб-панели (LittleFS)

# прошивка по Wi-Fi далее (ArduinoOTA)
pio run -e esp32dev_ota -t upload
# или по raw IP, если mDNS заблокирован:
pio run -e esp32dev_ota -t upload --upload-port 192.168.1.238
```

Во время OTA-передачи прошивка временно отписывает главный таск от
watchdog (ArduinoOTA принимает образ внутри блокирующего вызова `handle()`)
и приостанавливает запись телеметрии в LittleFS.

## Первый запуск

1. Без сохранённых Wi-Fi-учётных данных устройство поднимает точку доступа
   `FilamentDryer-Setup` — подключитесь и настройте сеть через веб-панель.
   Если станции не удаётся подключиться 60 с, setup-AP поднимается снова
   автоматически.
2. В домашней сети панель доступна по адресу `http://dryer.local` (mDNS; IP
   также показывается на дисплее).
3. Аутентификация опциональна: пустой веб-пароль отключает её. Если пароль
   задан, логин по умолчанию `admin` (настраивается), и тот же пароль
   защищает ArduinoOTA. Задайте пароль до подключения силовой части.

Перед подключением силовой части убедитесь, что GPIO26 остаётся в нуле при
старте, сбросе, ошибках NTC и во время OTA.

## REST API (кратко)

```
GET  /api/state        полный статус, включая телеметрию dryness.* и версию прошивки
GET  /api/config       настройки + список пресетов
PUT  /api/config       изменение настроек (Wi-Fi, авторизация, минимум вентилятора, весы...)
POST /api/run          запуск {mode, preset | temperatureC, durationSeconds...}
POST /api/stop         остановка
POST /api/pause        пауза / продолжение (переключатель)
GET  /api/history      телеметрия (окно JSONL)
GET  /api/events       журнал событий
GET  /api/calibration  статус калибровки весов
POST /api/calibration  операции tare / известная масса / дрейф-прогон
POST /api/ota          загрузка прошивки (multipart)
```

## Удалённая отладка

`tools/remote.ps1` опрашивает панель по Wi-Fi — USB-кабель не нужен:

```powershell
powershell -File tools\remote.ps1 status              # полный снимок состояния
powershell -File tools\remote.ps1 watch 3600          # живая телеметрия -> telemetry-*.jsonl
powershell -File tools\remote.ps1 history out.json    # скачать телеметрию
powershell -File tools\remote.ps1 events out.json     # скачать журнал событий
powershell -File tools\remote.ps1 ota                 # прошить .pio\build\esp32dev_ota\firmware.bin
```

Добавьте `-HostName 192.168.x.x`, если mDNS заблокирован в вашей сети.

## Тесты

Нативные юнит-тесты покрывают interlock актуаторов, полосу термостата,
границы каскада, цикл продувок, регрессию наклона AH, переходы dry→hold и
обратный отсчёт ручного режима:

```powershell
pio test -e native
```

```

data/              веб-панель (LittleFS)

```
